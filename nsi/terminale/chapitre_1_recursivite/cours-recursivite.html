1 Des poupées russes partout

Ouvrez une poupée russe : à l'intérieur, une autre poupée russe, un peu plus petite. Et à l'intérieur de celle-ci, encore une autre. Jusqu'à la toute petite, pleine, que l'on ne peut plus ouvrir. Pour expliquer à quoi ressemble une poupée russe, on peut dire : « c'est une poupée qui contient une poupée russe plus petite, sauf la dernière qui est pleine ». Cette définition se mord la queue — elle utilise le mot qu'elle cherche à définir — et pourtant elle est parfaitement claire.

Les ancêtres d'une personne

Les mathématiques regorgent de définitions de ce type. La suite factorielle, par exemple :

  • 0! = 1,
  • pour tout n ≥ 1, n! = n × (n − 1)!.

Pour calculer 4!, cette définition dit : « c'est 4 fois 3! ». Et pour 3! : « c'est 3 fois 2! ». Et ainsi de suite jusqu'à 0! qui vaut 1 par définition. On remonte alors : 1! = 1, 2! = 2, 3! = 6, 4! = 24. La définition se mord la queue elle aussi, mais chaque appel porte sur un entier strictement plus petit, et le premier cas (n = 0) fournit une réponse directe : on finit toujours par aboutir.

L'idée

Un objet est récursif quand il contient une copie plus petite de lui-même. Une fonction est récursive quand elle s'appelle elle-même. On programme ainsi tout ce qui a cette forme de « nuit étoilée dans la nuit étoilée » : suites définies par récurrence, parcours d'arbres, flocons, divisions pour régner.

2 Définition : les trois ingrédients

Définition

Une fonction récursive est une fonction dont la définition fait intervenir, au moins une fois, un appel à elle-même. Pour qu'elle fonctionne, elle doit respecter trois conditions :

  1. un ou plusieurs cas de base, où le résultat est connu directement, sans appel récursif ;
  2. un cas récursif, où le résultat est construit à partir d'un ou plusieurs appels à la fonction ;
  3. une convergence vers le cas de base : chaque appel récursif porte sur un sous-problème strictement plus petit, de sorte qu'après un nombre fini d'étapes on tombe sur un cas de base.

L'exemple canonique : la factorielle

On traduit directement la définition mathématique en Python :

def factorielle(n):
    if n == 0:                 # cas de base
        return 1
    return n * factorielle(n - 1)   # cas récursif : n − 1 est plus petit que n

factorielle(4)                       # → 24

Les trois ingrédients sont là : le cas de base n == 0 renvoie 1 sans appel ; le cas récursif renvoie n * factorielle(n − 1) ; et n − 1 < n, donc on se rapproche à chaque appel du cas de base.

Méthode — écrire une fonction récursive
  1. Choisir le paramètre qui mesure la « taille » du problème (ici n, ailleurs la longueur d'une liste, la hauteur d'un arbre…).
  2. Traiter le ou les cas de base : que vaut le résultat si la taille est minimale ?
  3. Écrire le cas récursif en supposant que la fonction fonctionne déjà sur un problème plus petit (hypothèse de récursion), et combiner ce résultat pour obtenir celui de la taille actuelle.
  4. Vérifier la convergence : chaque appel récursif porte-t-il sur un problème strictement plus petit ?

Trois autres fonctions, écrites avec la même méthode

# Somme des entiers de 1 à n : 1 + 2 + … + n
def somme(n):
    if n == 0:
        return 0
    return n + somme(n - 1)

# Longueur d'une chaîne, sans utiliser len()
def longueur(s):
    if s == "":                 # la chaîne vide : taille 0
        return 0
    return 1 + longueur(s[1:])     # on retire un caractère

# Puissance : x élevé à la n (n entier, n ≥ 0)
def puissance(x, n):
    if n == 0:
        return 1
    return x * puissance(x, n - 1)
Attention — le cas de base n'est pas facultatif

Oublier le cas de base, ou le placer après l'appel récursif, donne une fonction qui s'appelle elle-même sans jamais s'arrêter. Python finit par refuser (RecursionError: maximum recursion depth exceeded) : c'est le signal, en Python, d'une récursion mal pensée.

Une analogie : la récurrence au tableau

En mathématiques, prouver qu'une propriété P(n) est vraie pour tout n par récurrence demande deux choses : l'initialisation (P(0) vrai) et l'hérédité (P(n) ⇒ P(n + 1)). Les trois ingrédients d'une fonction récursive sont les mêmes : le cas de base joue le rôle de l'initialisation, le cas récursif celui de l'hérédité, et la convergence garantit que l'on balaye bien tous les entiers.

3 La pile d'appels

Quand factorielle(4) appelle factorielle(3), l'exécution de la première fonction est suspendue : Python met de côté sa variable n (qui vaut 4) et l'endroit du code où revenir, puis lance la deuxième. Celle-ci appelle factorielle(2), qui est encore suspendue, et ainsi de suite. Toutes ces exécutions en attente s'empilent les unes sur les autres dans la pile d'appels (call stack) : une pile au sens informatique du terme — dernier arrivé, premier servi.

Dérouler factorielle(4)

À chaque appel, un nouveau cadre (frame) empile n et l'adresse de retour. Au moment où le cas de base renvoie 1, la pile atteint sa taille maximale : 5 cadres. Puis chaque cadre est dépilé, en multipliant le résultat reçu par sa propre valeur de n.

Puis la pile se dépile, chaque cadre récupère le résultat du suivant et le multiplie par son propre n :

f(4) appelle f(3) … suspendu, n = 4 f(3) appelle f(2) … suspendu, n = 3 f(2) appelle f(1) … suspendu, n = 2 f(1) appelle f(0) … suspendu, n = 1 f(0) renvoie 1 cas de base f(1) renvoie 1 × 1 = 1 f(2) renvoie 2 × 1 = 2 f(3) renvoie 3 × 2 = 6 f(4) renvoie 4 × 6 = 24
À retenir

La pile d'appels mémorise, pour chaque fonction en cours, ses variables locales et l'endroit du code où reprendre. Sa taille maximale, pendant un calcul récursif, s'appelle la profondeur de récursion. Pour factorielle(n), la profondeur vaut n + 1.

La limite de Python

Python limite la profondeur de récursion à environ 1000 appels pour éviter de consommer toute la mémoire. Au-delà, l'exception RecursionError est levée. On peut l'augmenter avec sys.setrecursionlimit, mais c'est souvent le signe qu'il vaut mieux réécrire la fonction en itératif, ou qu'elle ne se rapproche pas assez vite du cas de base.

4 Récursif ou itératif ?

Tout ce qui s'écrit avec une récursion peut aussi s'écrire avec une boucle (c'est un théorème : les deux sont équivalents en puissance de calcul). Comparons factorielle dans les deux styles :

Version récursiveVersion itérative
def fact(n):
    if n == 0:
        return 1
    return n * fact(n - 1)
 
def fact(n):
    r = 1
    for k in range(1, n + 1):
        r = r * k
    return r

Quand préférer l'une ou l'autre

RécursifItératif
LisibilitéImbat­table quand le problème lui-même se décrit en termes de sous-problème (arbres, flocons, dichotomie, Hanoï).Imbat­table pour les parcours linéaires simples (for sur une liste, somme, moyenne…).
MémoireOccupe la pile proportionnellement à la profondeur de récursion.Mémoire constante en général : quelques variables qu'on met à jour.
RisquesDébordement de pile (RecursionError) si la récursion est trop profonde ; coût caché quand le même sous-problème est recalculé plusieurs fois (voir partie 6).Boucle infinie si la condition d'arrêt est mal écrite.
Exemples typiquesParcours d'arbre, dichotomie, tri fusion, Hanoï, flocon de Koch, backtracking.Somme, moyenne, max, parcours de tableau, recherche séquentielle.
Méthode — reconnaître un bon candidat à la récursion

Posez-vous : « puis-je décrire le problème en l'exprimant sur un sous-problème plus petit, de la même forme ? » Si oui, la récursion sera naturelle. Si l'énoncé parle d'un parcours de la gauche vers la droite sans structure hiérarchique, une boucle fera très bien l'affaire.

5 Diviser pour régner

La stratégie diviser pour régner (divide and conquer) consiste à :

  1. Diviser le problème en plusieurs sous-problèmes du même type, plus petits ;
  2. Résoudre récursivement chaque sous-problème ;
  3. Combiner les résultats pour obtenir celui du problème initial.

C'est l'une des idées algorithmiques les plus puissantes : elle fait souvent passer d'un coût en O(n) à un coût en O(log n), ou d'un coût en O(n²) à un coût en O(n log n).

La recherche dichotomique, en récursif

Dans un tableau trié, on cherche la valeur x. On regarde l'élément du milieu : si c'est x, c'est fini ; sinon, on relance la recherche sur la moitié qui peut encore contenir x. À chaque appel, la zone de recherche est divisée par deux : d'où log2(n) appels au plus.

def dichotomie(t, x, g=0, d=None):
    if d is None:
        d = len(t) - 1
    if g > d:
        return -1                      # cas de base : zone vide, absent
    m = (g + d) // 2
    if t[m] == x:
        return m                       # cas de base : trouvé
    if x < t[m]:
        return dichotomie(t, x, g, m - 1)   # moitié gauche
    return dichotomie(t, x, m + 1, d)       # moitié droite

dichotomie([1, 3, 4, 7, 9, 12, 15], 9)   # → 4

Le tri fusion

Pour trier un tableau, on le coupe en deux moitiés, on trie chacune récursivement, puis on fusionne les deux listes triées en une seule. Au bout du compte, l'algorithme fait O(n log n) opérations, bien mieux que les tris par sélection ou par insertion vus en Première (en O(n²)).

Tri fusion : les flèches violettes descendent (division en moitiés), les flèches vertes remontent (fusion de deux listes triées).
def fusion(a, b):            # fusionne deux listes triées en une seule, triée
    r, i, j = [], 0, 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            r.append(a[i]); i += 1
        else:
            r.append(b[j]); j += 1
    return r + a[i:] + b[j:]

def tri_fusion(t):
    if len(t) <= 1:
        return t                 # cas de base : déjà trié
    m = len(t) // 2
    g = tri_fusion(t[:m])        # trier la moitié gauche
    d = tri_fusion(t[m:])        # trier la moitié droite
    return fusion(g, d)           # combiner
Diviser pour régner, en résumé

À chaque étape le problème est réduit d'un facteur (souvent 2) et non d'une unité : la profondeur de récursion est en log n au lieu de n, et c'est ce qui change tout. On retrouvera cette idée partout : parcours d'arbres, exponentiation rapide, FFT, QuickSort, algorithmes géométriques.

6 Récursivité multiple

Jusqu'ici, chaque appel récursif en déclenchait un seul. Rien n'empêche d'en déclencher plusieurs : la fonction forme alors un véritable arbre d'appels.

La suite de Fibonacci

Elle est définie par F(0) = 0, F(1) = 1, et pour n ≥ 2 : F(n) = F(n − 1) + F(n − 2). Deux appels récursifs à chaque étage. La traduction en Python est immédiate :

def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
Arbre d'appels de fib(5). Les sous-arbres identiques (en orange) sont recalculés à partir de zéro à chaque fois.
Attention — le coût caché

Le nombre d'appels de fib(n) est de l'ordre de φn (avec φ ≈ 1,618). Pour n = 40, c'est plus de 300 millions d'appels : fib(40) prend plusieurs secondes alors qu'il y a seulement 41 valeurs à calculer. Une version itérative — ou récursive avec mémoïsation — règle le problème en 40 étapes.

# Version itérative : linéaire, en O(n)
def fib_iter(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a

# Version récursive mémoïsée : chaque fib(k) n'est calculé qu'une fois
def fib_memo(n, memo={}):
    if n < 2:
        return n
    if n not in memo:
        memo[n] = fib_memo(n - 1) + fib_memo(n - 2)
    return memo[n]

Les Tours de Hanoï

Trois tiges, n disques empilés par taille décroissante sur la tige de départ, les plus grands en bas. Il faut déplacer la tour sur la tige d'arrivée, en respectant deux règles : un seul disque à la fois, et jamais un grand disque sur un plus petit. L'algorithme récursif est d'une élégance rare :

Méthode — Hanoï à n disques, de la tige A vers la tige C via B
  1. Si n = 0, il n'y a rien à faire (cas de base).
  2. Déplacer n − 1 disques de A vers B, en utilisant C comme intermédiaire. (appel récursif)
  3. Déplacer le plus grand disque, le seul resté sur A, directement sur C.
  4. Déplacer les n − 1 disques de B vers C, en utilisant A comme intermédiaire. (deuxième appel récursif)
def hanoi(n, depart, arrivee, intermediaire):
    if n == 0:
        return
    hanoi(n - 1, depart, intermediaire, arrivee)
    print("déplacer un disque de", depart, "vers", arrivee)
    hanoi(n - 1, intermediaire, arrivee, depart)

hanoi(3, "A", "C", "B")

Pour n disques, l'algorithme effectue exactement 2n − 1 déplacements : 1 pour n = 1, 7 pour n = 3, 1023 pour n = 10. Si la légende de Brahma dit vrai (64 disques), 264 − 1 ≈ 1,8 × 1019 déplacements : plusieurs centaines de milliards d'années à raison d'un disque par seconde.

7 Les pièges classiques

1. Cas de base oublié

def compte(n):
    return 1 + compte(n - 1)      # où est l'arrêt ?

Sans test if n == 0: return 0, la fonction appelle compte(-1), puis compte(-2)… Rien ne l'arrête. Python finit par lever une RecursionError.

2. Convergence oubliée

def bizarre(n):
    if n == 0:
        return 0
    return bizarre(n + 1)         # on s'éloigne du cas de base

Le cas de base existe, mais chaque appel augmente n : on n'y arrivera jamais pour n = 1, 2… Même erreur à l'exécution.

3. Modifier un argument au mauvais moment

def somme(n):
    n = n - 1
    if n == 0:
        return 0
    return n + somme(n)             # appel avec le même n modifié : ambigu

Difficile à lire, et facile à se tromper d'un cran (on calcule la somme de 1 à n − 1 au lieu de 1 à n). Mieux vaut laisser le paramètre tel quel et ne modifier que l'argument des appels : return n + somme(n - 1).

4. Recalcul massif (cf. partie 6)

Deux appels récursifs qui portent sur les mêmes sous-problèmes font exploser le nombre total d'appels. Reconnaître ce schéma — « est-ce que je vais recalculer dix fois la même chose ? » — et le corriger par mémoïsation ou par une version itérative est un réflexe à prendre.

5. Confondre récursif et renvoyé

def longueur(s):
    if s == "":
        return 0
    longueur(s[1:])                   # appel récursif… dont le résultat est jeté
    return 1

La fonction appelle bien longueur sur s[1:], mais ne récupère pas son résultat avec un return : elle renvoie toujours 1, quelle que soit la longueur de la chaîne. Le bon code est return 1 + longueur(s[1:]).

Checklist avant de lancer une fonction récursive
  • Le cas de base est-il écrit ? Est-il avant le return récursif ?
  • Chaque appel récursif porte-t-il sur un argument strictement plus petit ?
  • Le résultat de chaque appel récursif est-il bien utilisé dans un return ou une expression ?
  • Puis-je prévoir la profondeur maximale (reste-t-elle sous 1000) ?
  • Est-ce que je recalcule plusieurs fois le même sous-problème ? Si oui, mémoïsation ou itératif.
