Ouverture du bloc — la séance « codage » pose les fondations matérielles : avant de demander ce qu'est une donnée, savoir en quoi elle est faite. Six manipulations (compteur binaire, octets d'un mot en UTF-8, grille de pixels, mélangeur RVB, échantillonnage d'une onde, échelle logarithmique).

Zoom sur l'étape 3 — la séance « neurone » ouvre la boîte noire laissée fermée par la précédente : elle répond à « d'un cheveu dans le bon sens — mais lequel ? ». Technique assumée (une formule par idée), mais aucun prérequis au-delà de la proportionnalité. Le mot biais y prend son second sens : la séance le dit explicitement. Elle se referme sur « une IA plus petite que Wikipédia », qui réutilise le codage du bloc pour expliquer l'origine des hallucinations.

Question de sortie (la charnière vers le bloc 4) : « Apprendre quelque chose au modèle nécessite-t-il toujours de le réentraîner ? » → réponse au bloc suivant : non, on peut aller chercher l'information.

4

Connecter l'IA au monde ★ morceau vedette

« Il faut aller chercher l'information. Où, et comment ? »
3 séances prêtes
RAGembeddings — en usage réel Internet ≠ Weble Web à l'ère de l'IA APIoù tourne le modèlepoids ouvertsoutils instructions systèmemémoire multimodalinjection d'instructions agents
▶ Chercher avant de répondre ▶ Internet, le Web et les API ▶ Anatomie d'un assistant

Ouverture du bloc — la séance « chercher avant de répondre » répond à la question de sortie du bloc 3 et pose les trois endroits où vit une information (appris · contexte · cherché). Les embeddings y passent de l'intuition à l'usage : carte des sens, puis une vraie parenthèse sur la notion de distance (Manhattan, euclidienne, cosinus — trois réponses pour les deux mêmes points), et le choix de l'angle pour le sens — puis le RAG en quatre temps, sa différence d'avec le fine-tuning, et ses quatre façons d'échouer. Elle se referme sur : « et s'il allait chercher tout seul ? » — d'où la suite : Internet, le Web et les API.

La séance 10 — « Internet, le Web et les API » remet les deux mots à leur place, lit une URL en quatre morceaux et suit le trajet d'une requête, parcourt les trois générations du Web sur un même besoin, puis ouvre la porte des programmes : une API, le JSON, et l'API d'un modèle qui est sans état — d'où le coût qui grimpe et la « mémoire » qui n'est pas dans le modèle. Elle se termine sur la question la plus concrète du bloc : site web, API ou sur ma machine — avec le poids d'un modèle en octets, la quantification et les trois degrés d'« ouvert ». Charnière : « et s'il frappait à ces portes lui-même ? » → les outils.

La progression technique — chaque étape ajoute une brique :
① une page Web GET → serveur → HTML · ② une API requête JSON → réponse JSON · ③ une API de LLM prompt → modèle → réponse · ④ un LLM avec outils le modèle choisit un outil · ⑤ un agent boucle observer → décider → agir.

La séance 11 — « Anatomie d'un assistant » ferme le bloc en démontant le produit : ce n'est pas un modèle, c'est un modèle plus cinq couches (interface, mémoire, outils, contexte, instructions système). Elle montre le cadre invisible, ce que le modèle relit vraiment à chaque tour, le fait qu'il n'exécute rien — il écrit un appel, le programme agit —, la boucle d'un agent avec son budget de tours, le multimodal, les trois mémoires, et quatre pannes nommées par couche, dont l'injection d'instructions. C'est de fait la révision de tout le cours : la manipulation « qui fait le travail ? » rappelle chaque brique des blocs 1 à 4. Charnière vers le bloc 5.

Ce qui reste du bloc — la question « un Web écrit par qui, lu par qui ? » (contenus synthétiques, provenance, crédibilité) est déplacée au bloc 6, où elle rejoint les réseaux sociaux.

Les trois générations du Web : documentaire (je connais une adresse) → moteurs de recherche (je cherche des pages) → à l'ère de l'IA (je formule une intention). Soit URL → mots-clés → intention.

Et le Web change des deux côtés : « un Web écrit par qui… et lu par qui ? » → contenus synthétiques, provenance, crédibilité. Question ouverte savoureuse : si une IA répond sans que je visite le site, que devient le Web ?

Les fils rouges

① L'information — le fil qui traverse tout

les tokens la représentent → les données servent à l'apprendre → les embeddings l'organisent → le RAG la retrouve → Internet la transporte → le Web la publie → les API la structurent pour les machines → les agents vont la chercher et agissent → les réseaux sociaux la sélectionnent → le génératif la produit → l'esprit critique décide si on lui fait confiance

② L'assistant du lycée — le projet cumulatif (bloc 4)

Au début, le modèle ne sait rien du lycée. Puis, étape par étape : ① une info dans le prompt → ② plusieurs documents → ③ un RAG (conceptuel) → ④ un appel d'API → ⑤ une info récupérée sur le Web → ⑥ un petit agent.
À chaque étape, la même question : « qu'est-ce que notre système sait faire maintenant qu'il ne savait pas faire avant ? »
Réalisable en version conceptuelle (sans infrastructure) ou mains dans le cambouis si la plateforme le permet — ce n'est pas le même coût en heures.

③ Le biais — né technique, revenu politique

Introduit mécaniquement au bloc 3 (d'où vient un biais dans les données), puis repris comme enjeu de société au bloc 7. Les élèves reconnaissent une notion déjà vue : ça soude le cours.

④ Les idées reçues — une séance, puis des rappels

La séance du bloc 1 sert de réservoir. On re-pique une idée reçue dans les blocs suivants — surtout « un LLM ne cherche pas sur Internet » au bloc 4, où l'on distingue enfin : ce que le modèle sait · ce qu'on met dans son contexte · ce que le RAG retrouve · ce qu'un outil va chercher.

⑤ Émerveillement → démontage → reconstruction

L'accroche montre ce qu'un système moderne sait faire, sans expliquer. Des semaines plus tard, au bloc 4 : « vous vous souvenez du premier cours ? Maintenant vous pouvez expliquer ce qui se passait sous le capot. » Les entrées « l'IA sort de l'écran », « elle s'échappe de son bac à sable » de la frise deviennent enfin lisibles.
